# 轻跳 / LIGHT SKIP
## Android 开屏广告自动跳过 · 产品与实现方案

> 少等一秒，直接进入。

---

## 1. 产品定义

**一句话**：当用户打开已守护的应用时，轻跳在本机识别开屏广告里的「跳过」按钮并自动点击，让用户直接进入应用。

**目标用户**
- 每天高频打开多个 App，厌倦 3–5 秒开屏广告的人。
- 在意隐私、不希望授予联网、悬浮窗、使用情况访问等额外权限的人。
- 愿意手动开启一次无障碍服务，换取长期无感体验的人。

**不做什么**
- 不做广告拦截器，不修改目标 App，不破解会员。
- 不截图、不做 OCR、不上传屏幕内容。
- 不申请网络权限，不做账号体系，不接广告或统计 SDK。
- 不做常驻悬浮窗，不做后台轮询。

**品牌语气**：安静、可信、克制、工具感。避免游戏化、夸张营销和「秒杀广告」之类的表达。

## 2. 核心体验

### 初始化流程

`欢迎页 → 无障碍授权 → 自动推荐应用 → 首页`

1. 欢迎页只讲一件事：打开应用时帮你点掉开屏广告。
2. 授权页明确告诉用户：只开一个权限、只在开屏时工作、内容不出手机。
3. 授权完成后，根据桌面可见应用生成推荐清单，默认开启常见高频 App。
4. 进入首页，展示守护状态与今日统计。

### 日常使用

- 用户打开已守护的 App。
- 无障碍服务收到窗口变化事件，确认目标包名在守护清单内。
- 启动一次最长 6 秒的短会话，最多尝试 3 次。
- 找到「跳过」类按钮后优先执行 `ACTION_CLICK`，必要时用 `dispatchGesture` 兜底。
- 点击成功或超时后立即结束会话，回到完全空闲状态。

### 关键原则

- **一次只做一件事**：每个页面只有一个主操作。
- **状态优先**：首页先回答「现在有没有在守护」，再展示统计。
- **可解释**：权限、识别范围、网络权限都明确写出来。
- **可退出**：用户随时可以在系统设置里关闭无障碍服务。

## 3. 五个页面

### 01 欢迎

- Logo、产品名、Slogan。
- 开屏广告与点击环插画，直观表达「自动点跳过」。
- 三个卖点：本地识别、无网络权限、自动休眠。
- 主 CTA：`开始设置`。
- 辅助文案：`无需 Root · 无需注册 · 不含广告 SDK`。

### 02 授权

- 步骤 `1 / 2`。
- 标题：`只开一个权限，换回每次开屏。`
- 无障碍服务卡片，展示系统路径：
  `设置 › 无障碍 › 已下载的应用 › 轻跳`
- 信任说明：
  - 只在开屏时工作：目标应用进入前台后最多检测 6 秒。
  - 只看文字和按钮：不读取输入框，不保存屏幕画面。
  - 内容不出手机：没有网络权限，数据只留在本机。
- Android 13+ 受限设置提示。
- 明确说明：系统不会自动开启，用户可随时关闭。

### 03 首页

- 守护中状态与总开关。
- 今日跳过次数示例 `08`。
- `约省下 12 秒等待`，标注「示意」。
- 上次拦截：`小红书 · 刚刚`。
- 平均响应 `0.4 秒`、今日耗电 `<0.1%`，均标注「示意 / DEMO」。
- 快捷设置：
  - 仅开屏时识别
  - 点击后轻震
  - 检测窗口 `6 秒 · 最多尝试 3 次`
- 守护范围 `28 个应用`。

### 04 应用

- 标题：`选择要守护的应用`。
- 摘要：`28 个已启用 · 4 个已排除`。
- 分段筛选：`全部 32 / 已启用 28 / 已排除 4`。
- 搜索框。
- 显示桌面可见应用（包括系统浏览器等预装应用），不申请 `QUERY_ALL_PACKAGES`。
- 每个 App 独立开关。右上角提供「全选 / 清空」快捷操作。
- 示例：微博、小红书、知乎、淘宝、网易云音乐、哔哩哔哩、高德地图。
- 使用彩色首字母图标，不使用品牌 Logo。
- 底部说明：新安装应用可手动加入，不申请 `QUERY_ALL_PACKAGES`。

### 05 设置

- 状态卡：`守护正常`，无障碍服务已连接。
- 识别设置：检测窗口、最多尝试次数、识别「关闭广告」开关。
- 无文字 `×` 默认关闭，避免误触。
- 反馈与记录：点击轻震、本地统计。
- 网络权限显示 `未申请`。
- 数据：清除统计、隐私说明。
- 后台稳定运行：打开系统电池优化设置，不申请特殊忽略权限。
- 版本：`轻跳 0.1`。

- 点击区域至少 `48dp`。
- 正文对比度至少 `4.5:1`。
- 支持系统字体缩放，布局不因放大而截断。
- 支持「减少动画」设置。

## 5. 技术实现

### 5.1 技术选型

- 包名：`com.lightskip.app`
- `minSdk 26`（Android 8.0+），`targetSdk 35`
- Kotlin + 原生 Views + ViewBinding，不使用 Jetpack Compose
- 单 Activity + 3 个主 Fragment（首页 / 应用 / 设置），引导页独立
- `SharedPreferences` 保存设置与统计，不使用 Room
- 不引入网络库、依赖注入、统计 SDK、广告 SDK
- Release 开启 R8 与资源压缩

这样做的目的不是「为了小而小」，而是减少启动路径、方法数、后台组件和权限面。

### 5.2 建议模块

| 模块 | 职责 |
| --- | --- |
| `MainActivity` | 主容器、底部导航、权限状态刷新 |
| `OnboardingActivity` | 欢迎、授权引导、初始应用推荐 |
| `SkipAccessibilityService` | 接收窗口事件，启动/结束短会话 |
| `SkipSessionController` | 6 秒窗口、3 次尝试、状态机、去重 |
| `NodeScanner` | 有界遍历节点树，找候选按钮 |
| `RuleEngine` | 文本归一化、规则匹配、候选打分 |
| `AppRepository` | 读取桌面可见应用、维护守护清单 |
| `Prefs` | 设置、守护包名集合、统计开关 |
| `LocalStats` | 按天计数、上次拦截、清理 |

### 5.3 无障碍服务配置

Manifest：

```xml
<service
    android:name=".service.SkipAccessibilityService"
    android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE"
    android:exported="true">
    <intent-filter>
        <action android:name="android.accessibilityservice.AccessibilityService" />
    </intent-filter>
    <meta-data
        android:name="android.accessibilityservice"
        android:resource="@xml/accessibility_service_config" />
</service>
```

`res/xml/accessibility_service_config.xml`：

```xml
<accessibility-service
    android:accessibilityEventTypes="typeWindowStateChanged|typeWindowContentChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagReportViewIds|flagIncludeNotImportantViews"
    android:canRetrieveWindowContent="true"
    android:canPerformGestures="true"
    android:notificationTimeout="100"
    android:description="@string/accessibility_description" />
```

说明：
- 只监听窗口状态与内容变化，不监听滚动、触摸、文本输入。
- `flagIncludeNotImportantViews` 用于覆盖部分自定义开屏容器，但扫描必须做深度和数量限制。
- `notificationTimeout` 设为 100ms，避免高频事件把服务叫醒太多次。
- `canPerformGestures` 仅在 `ACTION_CLICK` 失败时用于坐标点击兜底。

### 5.4 会话状态机

```text
IDLE
  └─ 目标包名进入前台 → ARMED
        └─ 开始扫描 → SCANNING
              ├─ 命中并点击成功 → CLICKED → IDLE
              ├─ 达到 3 次尝试 → IDLE
              └─ 超过 6 秒 → EXPIRED → IDLE
```

实现要点：
- 监听 `TYPE_WINDOW_STATE_CHANGED`，确认 `event.packageName` 在守护清单内。
- 启动会话时记录 `deadline = now + 6000ms`、`attempts = 0`。
- 会话内响应 `TYPE_WINDOW_CONTENT_CHANGED`，并补 2–3 个短延迟检查（例如 0ms / 250ms / 800ms），覆盖广告延迟渲染。
- 成功、超时或达到尝试上限后，取消所有 Handler 回调，立即回到 IDLE。
- 不做 `while` 轮询，不持有 `AccessibilityNodeInfo`，不保存节点树。

### 5.5 节点扫描

- 从 `rootInActiveWindow` 做 BFS。
- 深度上限 20，节点上限 500，避免在复杂页面上耗时。
- 只处理可见节点；读取 `text` 与 `contentDescription`。
- 候选节点向上找最多 3 层可点击祖先。
- 位置启发式：优先右上与右下两个常见跳过位置；不硬性排除底部，避免漏掉 B 站这类右下角按钮。
- 只接受与当前前台包名一致的节点。
- 不读取输入框内容，不记录节点文本，不截图。

### 5.6 文本规则

归一化：去首尾空格、去多余空白、全角转半角、英文转小写、去掉倒计时中的 `s` / `秒` 后再匹配。

默认启用：

```text
^跳过(广告)?$
^跳过\s*\d{1,2}\s*(s|秒)?$
^\d{1,2}\s*(s|秒)?\s*跳过$
^跳过广告\s*\d{1,2}$
```

默认关闭、需要用户手动开启：

```text
^关闭广告$
```

拒绝或降权：
- 文本过长且不属于倒计时格式。
- 包含「跳过此内容」「跳过介绍」「跳过引导」等非开屏语义。
- 位于屏幕中央内容区或可滚动列表内部。
- 同一个文本 + 同一组 bounds 在 1.5 秒内重复出现。

候选打分 = 文本精确度 + 可点击性 + 位置 + 控件尺寸。取最高分，仅点击一次。

### 5.7 点击策略

1. 优先对可点击祖先执行 `ACTION_CLICK`。
2. 失败时，用 `dispatchGesture` 在节点 bounds 中心点按一次。
3. 点击后不立即重复点击；等待 300ms 观察窗口变化，再决定是否结束。
4. 轻震通过 `Vibrator` / `VibratorManager` 触发一次短反馈，可在设置中关闭。

### 5.8 应用列表与包可见性

- 不申请 `QUERY_ALL_PACKAGES`。
- 在 Manifest 中声明 `<queries>`，只让系统返回桌面启动器应用：

```xml
<queries>
    <intent>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent>
</queries>
```

- 用 `PackageManager.queryIntentActivities` 读取，按包名去重，过滤轻跳自身。
- 守护清单用 `StringSet` 存入 `SharedPreferences`。
- 新安装应用通过「刷新应用列表」手动加入，不注册 `PACKAGE_ADDED` 常驻广播。

### 5.9 本地数据

- 设置：总开关、守护包名集合、检测窗口、尝试次数、关闭广告开关、轻震、统计开关。
- 统计：按天计数 `stats_yyyyMMdd`、上次拦截包名、上次拦截时间。
- 只保留最近 30 天，应用启动时清理过期键。
- 不保存完整界面文本、不保存截图、不保存广告内容。

### 5.10 权限清单

需要：
- `BIND_ACCESSIBILITY_SERVICE`（服务级，由系统绑定）
- `VIBRATE`（可选反馈）

明确不申请：
- `INTERNET`
- `QUERY_ALL_PACKAGES`
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
- `SYSTEM_ALERT_WINDOW`
- `PACKAGE_USAGE_STATS`
- `RECEIVE_BOOT_COMPLETED`
- `FOREGROUND_SERVICE`
- `WAKE_LOCK`

Android 13+ 侧载应用可能需要用户在「应用信息」中允许「受限设置」，之后才能开启无障碍服务。引导页必须写清楚。

## 6. 轻量化与省电策略

- **事件驱动**：没有常驻轮询，没有定时任务，没有后台线程池。
- **短会话**：每次最多 6 秒、最多 3 次尝试，结束即停。
- **无常驻组件**：不建前台服务、不开机自启、不持有 WakeLock、不注册闹钟。
- **无重依赖**：不用 Compose、Room、WorkManager、网络库、统计 SDK。
- **资源精简**：VectorDrawable、系统字体、R8、资源压缩、移除未使用资源。
- **启动精简**：`Application.onCreate` 不做重活，统计清理延迟到首屏后。
- **写盘克制**：统计使用 `SharedPreferences.apply()`，不频繁同步写。

APK 体积预期 `0.5–1.5 MB`，但这是工程判断，不是承诺；必须构建后实测并记录。

## 7. 隐私与合规

- 无障碍服务能读取界面内容，必须在应用内和隐私政策中明确说明用途。
- 只处理与「跳过」按钮匹配的文本，其他文本立即丢弃，不落盘。
- 没有网络权限，数据在系统层面无法离开设备。
- 不读取密码、聊天内容、输入框内容，不保存屏幕画面。
- 部分目标 App 的用户协议可能禁止自动化操作，用户需自行判断。
- **Google Play 政策风险**：使用无障碍 API 实现广告跳过，可能被认定为非无障碍用途而拒绝上架。更现实的路径是侧载、企业分发或替代应用商店。不要在上架材料中伪装用途。

---

## 8. 已知限制

- 无法保证 100% 跳过。
- 纯图片、Canvas 绘制、WebView 内部、`FLAG_SECURE` 页面可能没有可读文本节点。
- 自定义绘制且没有无障碍标签的按钮无法识别。
- 跳过按钮在倒计时结束前隐藏的广告，只能在 6 秒窗口内等待。
- 部分 App 的正常内容里也有「跳过」，位置启发式只能降低误触，不能完全消除。
- 无文字 `×` 和「关闭广告」默认关闭，因为误触风险高。
- OEM 省电策略可能延迟或终止服务；只能在必要时引导用户关闭针对本应用的省电限制。
- 守护全部应用会增加会话次数与误触概率，建议只保留有开屏广告的 20–30 个应用。
- 平板、折叠屏、分屏下的坐标启发式需要额外适配。

- 任何联网能力

## 10. 验收标准

- 已守护的测试 App，出现「跳过 5」时，10 次中至少 9 次在 1 秒内完成点击。
- 未守护的 App 不产生任何点击。
- 单次会话不超过 6 秒，尝试不超过 3 次。
- Manifest 中不存在 `INTERNET` 权限。
- Release APK 构建后记录真实体积，目标不超过 2 MB。
- 中端机冷启动可接受，首屏不进行重初始化。
- 1 小时典型使用耗电低于 1%（真机实测，不写死为宣传数据）。
- 30 分钟 monkey 测试无崩溃、无 ANR。
- 字体放大 1.3 倍后，5 个页面无截断、无重叠。
- 所有点击区域不小于 48dp。
