# 轻跳 v0.2：兼容、弹窗学习与发热优化

## 1. 背景

反馈机型为 **Redmi K70 / HyperOS 3.0.307.0**。问题包括：

- QQ 音乐、百度地图等应用无法稳定跳过开屏；
- B 站快速关闭再打开时偶发漏跳；
- 自动识别右上角 X 会误点 WPS 的正常关闭按钮、QQ 的加号；
- 开启无障碍后存在发热反馈；
- 用户希望应用内弹窗也能自动关闭，但不能误触正常 UI。

此外，MEIZU 21 上用于回归开屏、弹窗学习、连续多广告和后台占用。

## 2. 最终策略

### 2.1 开屏

- 目标 App 进入前台后开启短会话。
- 兼容模式：10 秒 / 最多 5 次点击。
- 只扫描目标包名窗口，不遍历系统 UI/输入法。
- 支持「跳过」文字、`skip`/`jump` 资源 ID、右上/右下位置。
- `ACTION_CLICK` 失败时使用 `dispatchGesture` 兜底。
- 同一 App 结束会话后 2 秒冷却，修复快速重开被 8 秒冷却挡住的问题。

### 2.2 应用内弹窗

- 默认关闭，只在用户完成学习后执行。
- 不再自动扫右上角 X，不再使用未学习的通用位置规则。
- 每个 App 最多保存 5 条关闭规则。
- 规则优先级：
  1. `viewId`
  2. `contentDescription`
  3. class + 相对区域
  4. 无元数据时：相对区域 + 小型可点击节点确认
- 只有学习模式会记录点击，正常使用不会自动扩张规则。

### 2.3 学习模式

最终交互：

1. 用户选择要学习的 App。
2. 轻跳自动打开该 App。
3. 轻跳先处理开屏；检测到跳过成功，或等待初始化结束后，进入记录状态。
4. 用户逐个点击弹窗广告的小 X。
5. 每个新按钮记录一条规则；重复按钮不重复计数。
6. 继续点击下一个广告的 X，最多记录 5 个。
7. 返回轻跳、再点一次「学习关闭按钮」或记录满 5 个后结束。

这样同一 App 有多个广告时不需要重复开始学习，每个 X 都能单独保存。

### 2.4 误触保护

- 学习点击必须先通过“小型关闭控件”验证。
- 默认拒绝大卡片、整块内容区域和宽按钮。
- 文本包含「跳过」的点击会被拒绝，避免把开屏按钮学成弹窗关闭。
- 无 id/desc 的区域规则在执行前必须在该区域找到小型可点击节点，不会盲点坐标。

## 3. 发热优化

### 3.1 动态无障碍事件

空闲：

```text
TYPE_WINDOW_STATE_CHANGED
TYPE_WINDOWS_CHANGED
TYPE_VIEW_CLICKED
```

仅在开屏或弹窗短会话期间增加：

```text
TYPE_WINDOW_CONTENT_CHANGED
FLAG_RETRIEVE_INTERACTIVE_WINDOWS
```

会话结束立即恢复低频配置。这样空闲时不再接收所有应用的 `TYPE_WINDOW_CONTENT_CHANGED` 事件。

### 3.2 扫描预算

- 通知合并间隔：`100ms`
- 最大节点：`400`
- 最大深度：`14`
- 只遍历目标包名窗口
- 开屏兼容模式最多 8 次扫描，普通模式 5 次
- 内容变化最多触发 3/2 次扫描
- 内容防抖：开屏 `240ms`，弹窗 `300ms`
- 高置信度开屏候选提前结束遍历

### 3.3 高频读取缓存

- 守护包名集合使用进程内不可变缓存。
- 不再在每次无障碍事件里复制 100+ 个包名。
- 诊断日志只记录窗口状态、窗口变化、学习点击，不记录高频内容变化。
- 学习规则按 App 缓存，避免每次扫描重复解析 JSON。

## 5. 仍需复测

- Redmi K70 / HyperOS 3.0.307.0
- QQ 音乐开屏
- 百度地图开屏
- B 站快速关闭再打开
- 真实应用内广告双 X / 多弹窗场景
- 不同 OEM 的“无障碍已开启但未连接”恢复路径

Xiaomi 17 发热问题没有实机复现条件；当前完成的是事件订阅、扫描频率、节点预算和后台占用层面的结构性优化，仍需该用户使用新版本复测。

## 6. 一句话总结

v0.2 不再猜广告：开屏用有界扫描，弹窗只用学习规则；学习一次可以连续记录多个关闭按钮，同时把无障碍事件和节点遍历压到短会话内。
